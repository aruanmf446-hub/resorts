# THE WORLD BEYOND — Resort Experience 2026

> *A destination you can feel before you arrive.*

A white-label, immersive website template for resorts. It covers a cinematic arrival, an explorable 3D resort world, signature experiences, villas, gastronomy, wellness, a stay planner and an elegant hand-off to external booking engines. Everything is driven by one typed, validated configuration file per resort.

It is a **static site** (Astro + TypeScript + GSAP + Three.js). There is no database, backend, CMS or paid API, and it deploys to Cloudflare Pages, Vercel or any CDN.

## The three demonstration presets

All three run on the same code and component library. Only the preset folder differs.

| Motion | Cinematic | Cinematic | Subtle |
| Booking | External engine (URL + params) | WhatsApp | E-mail |

> All brands, places, activities and images in the presets are **fictional demonstration content**. The images are original artwork generated by `scripts/generate-art.mjs`, and the 3D maps and films are rendered from the template's own 3D world. No testimonials, awards, prices or availability are invented. The testimonials section ships disabled with a placeholder.

## Quick start

```bash
npm install
```

```bash
npm run dev:coastal
```

The other presets run with `npm run dev:mountain` and `npm run dev:wellness`.

```bash
npm run build:all
```

`build:all` writes each preset to `dist/coastal`, `dist/mountain` and `dist/wellness`. A plain `npm run build` builds the preset named in `RESORT_PRESET` (default `coastal`) into `dist/`.

```bash
npm test
```

`npm test` runs the unit tests, all three builds and the end-to-end browser suite.

## Architecture

```
src/
  config/           schema.ts (zod contracts) · index.ts (loads + cross-validates the active preset)
  presets/<id>/     ← EVERYTHING client-specific lives here (one file)
  sections/         38 section types → 28 art-directed components + registry.ts + schemas.ts
  components/       layout pieces: Header, Menu, Footer, WorldMap, BookingForm, details…
  scripts/          motion.ts (GSAP language) · world/ (3D engine) · map.ts · villa.ts · planner.ts · booking.ts · sound.ts
  lib/              links (token resolver) · booking (pure URL/validation helpers) · theme (tokens) · context
  i18n/ui.ts        interface strings (en, pt-BR)
  pages/[...path].astro   one route generates every enabled page, villa and experience
public/media/<id>/  images, films, panoramas, maps, PDFs per preset
public/models/      GLB/GLTF models
scripts/            asset generators (art, renders/films, GLB)
tests/              unit (tsx --test) + end-to-end (Playwright)
docs/CUSTOMIZATION.md  step-by-step guide for new instances
```

Key principles:

- **One source of truth.** Components never contain client data. They read the validated preset.
- **Validated at build.** Schema errors, unknown POIs or categories, duplicate slugs, missing booking settings and malformed section content all fail the build with a readable list.
- **No broken links.** Internal links are tokens (`page:map`, `stay:cliff-villa`, `poi:spa`, `booking`…). A token pointing to a disabled page or item resolves to nothing, and the button is not rendered.
- **Optional everything.** Sections, pages, the 3D world, sound, villa explorer, panorama and booking are all optional, and removing one never leaves gaps.
- **Progressive 3D.** An illustrated map and an accessible list of places render first, and WebGL mounts on top only when the device can handle it.

## The 3D resort world

`src/scripts/world/` is a self-contained engine:

- **Terrain**: seeded procedural `island`, `valley`, `terraces` or `dunes`, with flattened pads under buildings and topographic contour lines (shader). Non-island worlds are presented as an architectural diorama (cut section and plinth).
- **Water**: depth-tinted shallows from a height texture, shoreline foam, fresnel sky reflection and sun glints.
- **Vegetation**: instanced palms, pines, cypress or broadleaf, with GPU wind sway and season tinting.
- **Architecture**: maquette-style villas, bungalows, overwater residences, pavilions, pools, spa, cabins, lodge, tower, deck, jetty and garden, generated from each POI's `structure`.
- **Atmosphere**: sky dome with stars, fog, clouds and GPU particles (pollen, fireflies, snow, mist). Dawn, day, dusk and night are animated presets that also light the windows. Seasons repaint the terrain and trees.
- **Interaction**: orbit, zoom and pan with limits, HTML hotspots, camera flights to places, a category filter, a panel with image and link, `#poi-<id>` deep links and idle auto-orbit.
- **Robustness**: capability detection (WebGL2, memory, cores, Save-Data, `?webgl=0`), quality tiers, automatic degradation under low FPS, pausing when offscreen or the tab is hidden, context-loss handling and full GPU disposal.
- **GLB/GLTF**: `world.mode: 'model'` loads a client model (Meshopt supported) and drops hotspots onto it by raycast. The villa explorer loads `stay.model.src` (demo: `public/models/villa.glb`) and falls back to the procedural villa.

## Testing

| Command | What it checks |
|---|---|
| `npm run test:unit` | Booking URL mapping per provider, date validation, link resolution with disabled pages, section ordering and removal, preset validation and the three-preset distinctness check |
| `npm run build:all` | Static build of every preset (fails on any config error) |
| `npm run test:e2e` | Every page of every preset in Chromium: no console errors, no broken internal links, hotspots and 3D map, no-WebGL fallback, reduced motion, booking hand-off URL and date validation, planner, menu and keyboard, mobile layout, SEO tags, sitemap, absence of secrets in the bundle |

See `docs/CUSTOMIZATION.md` for the full guide to creating a new resort.
